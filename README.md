# RISC-V SystemVerilog Microarchitecture

UCL ELEC0028 Advanced Digital Design — Coursework 2 (individual)

## Overview

**Part I — RISC-V microarchitecture design, SystemVerilog and simulation.**
Starting from a base single-cycle RISC-V datapath, this extends the
microarchitecture to support `jal` and `jalr`, which the base design cannot
execute: both require a `PC+4 -> rd` write-back path (absent from the
``ResultSrc`` mux), and `jalr` additionally needs an `rs1 + imm -> PC` route
that the base `PCSrc` mux doesn't provide. Three additions close the gap: a
feedback path from `ALUResult` to the `PCSrc` mux (for `jalr`), a path from
`PCPlus4` into the `ResultSrc` mux (for `jal`/`jalr` return addresses), and
routing the ALU `Negative` flag to the control unit (for `blt`/`bge`).

Each sub-block (program counter, control unit, extend module, ALU, plus the
pre-written instruction memory, register file, and data memory/IO) is
implemented in SystemVerilog with its own testbench, then integrated into a
top-level module and verified by running and disassembling a full test
program.

**Part II — RISC-V assembly programming.** Two hand-written RISC-V assembly
programs, verified on an emulator and simulated on the Part I datapath:
counting the number of 1s in an input byte, and multiplication via the
shift-and-add algorithm.

rtl/         SystemVerilog source modules (program counter, control unit,
             extend, ALU, register file, data memory/IO, instruction memory,
             top-level risc_v.sv)
tb/          Testbenches for each module and the top-level integration

\`.gitignore\` since it's regenerated by re-running the testbenches.
